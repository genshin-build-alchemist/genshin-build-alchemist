# 고정 평가셋 (data/eval)

모든 실험(baseline → prompt_v2 → rag → rag_v3 → rag+lora)은 **같은 질문 목록**으로 채점해야 점수를 비교할 수 있습니다.
그래서 질문 목록을 한 번 만들어 고정하고, 지문(sha256)으로 바뀌지 않았는지 확인합니다.

## 현재 고정본

| 항목 | 값 |
|---|---|
| 파일 | `questions_info_v1.json` |
| dataset_version | `info_v1` |
| 지문 (sha256) | `2e5f54373b7ba38551cf401042df1efcde916fba2e0f9df48462c2f3cb5b50c7` |
| 데이터 | genshin-db 한국어 `49a6544` (7.1), 캐릭터 124명 |
| 질문 수 | 611개 = 학습 496 (lookup 397, filter 91, unknown 8) + 평가 115 (lookup 82, filter 25, unknown 8) |
| 평가용 캐릭터 | 22명 (`eval_characters`), 학습용 질문의 정답·캐릭터에 나오지 않음 |

지문은 `questions` 목록을 `json.dumps(qs, ensure_ascii=False, sort_keys=True, separators=(",", ":"))`로 바꾼 뒤 sha256을 구한 값입니다.
키 순서나 들여쓰기가 달라도 내용이 같으면 같은 지문이 나옵니다.

## 어디에 있나

- **저장소** `data/eval/questions_info_v1.json`: 유일한 원본. 테스트(`tests/test_evalset.py`, `tests/test_eval_routing.py`)가 지문, 분리 규칙, 라우터·검색 결과를 검사합니다.
- 노트북(`notebooks/01_eval_info.ipynb`)은 셀 1에서 저장소를 받아 와 이 파일을 읽고, 지문이 다르면 멈춥니다.
- 새 버전 고정본이 아직 저장소에 없을 때만 노트북이 만들어 드라이브 `data/`에 저장합니다. 그 파일을 PR로 이 폴더에 올립니다.

## 규칙

1. **고정본 파일을 손으로 고치지 않습니다.** 고치면 노트북과 테스트가 바로 멈춥니다.
2. 평가 문항(`split: eval`)과 평가용 캐릭터는 프롬프트 예시, 파인튜닝 데이터에 쓰지 않습니다.
3. 질문 생성 규칙이나 데이터를 바꿔야 하면 **새 버전**을 만듭니다.
   - 노트북의 `DATASET_VERSION`을 `info_v2`로 올리고 `EXPECTED_SHA256`을 새 지문으로 바꿉니다.
   - 새 파일 `questions_info_v2.json`을 저장소에 추가하고 이 README와 테스트의 지문을 고칩니다.
   - 이전 버전 결과와 새 버전 결과는 점수를 직접 비교하지 않습니다 (결과 JSON의 `dataset_version`으로 구분).
4. 사람이 만든 질문(`human_questions.csv`)은 이 파일과 따로 관리하고, 평가에만 씁니다.

## 사람이 만든 질문 (human_questions.csv)

자동 생성 질문은 문장이 정형화돼 있어서, 실제 유저 말투(줄임말, 오타, 별명)를 라우터가 알아듣는지는 사람 질문으로 확인합니다.

**쓰는 사람은 질문과 target만 적습니다. 정답은 데이터에서 자동으로 채웁니다.**
양식: `human_questions_template.csv` (구글 스프레드시트에서 써도 되고, 다 쓰면 CSV로 내려받기)

| question | target | 정답 (자동) |
|---|---|---|
| 알베도 속성 뭐임? | `알베도/원소` | 바위 |
| 몬드 5성 누구누구 있어? | `지역=몬드, 성급=5성` | 다이루크, 두린, ... |
| 원신에서 제일 센 캐릭터는? | (빈칸) | [] |

- target 항목 이름: 원소, 무기, 성급, 지역. 값은 `5`, `5성급`, `불원소`, `몬드 출신`처럼 써도 맞춰 줍니다.
- 질문 문장은 해석하지 않고 target만 봅니다. 그래서 라우터가 질문을 잘못 알아들어도 정답이 오염되지 않습니다.
- 다 쓴 CSV를 드라이브 `data/human_questions.csv`로 올리면 노트북 셀 12가 정답을 채워 평가합니다. 이름 오타 같은 오류 줄은 "혹시: 알베도" 식으로 알려 주고 평가에서 뺍니다.
- 미리 확인하려면: `python3 -m core.human_questions human_questions.csv` → `human_questions_filled.csv`와 오류 목록

## 말투 변형 질문 (style_questions_*.csv)

C가 만든 질문 원본(드라이브 `data/질문_원본/`)에서 뽑았습니다. 같은 질문을 말투만 바꿔 물었을 때 라우터와 답이 버티는지 봅니다.
원본 질문 id는 `note` 칸 괄호 안에 남겨 두었습니다.

| 파일 | 개수 | 캐릭터 | 용도 |
|---|---|---|---|
| `style_questions_dev.csv` | 1,748 | 학습용 캐릭터 102명 | **개발용**. 라우터·프롬프트를 고칠 때 마음껏 봐도 됨 |
| `style_questions_v1.csv` | 246 | 평가용 캐릭터 22명 | **평가용**. 고친 뒤 한 번만 확인. 항목마다 짧은 반말·존댓말·띄어쓰기 없음 1개씩 (82개씩) |

- 라우터만 빠르게 점검 (GPU 없이 몇 초): `python3 -m core.route_check data/eval/style_questions_dev.csv`
- 모델까지 평가하려면 `style_questions_v1.csv`를 드라이브 `data/human_questions.csv` 자리에 두거나 노트북 셀 12의 경로를 바꿔 돌립니다 (4방법 약 30분).
- 지금 라우터 결과 (개선 전 기준): 짧은 반말·존댓말 약 91~96%, **띄어쓰기 없음 0%**, 줄임 이름("카즈하", "헤이조")도 못 찾음 → B의 개선 대상
- 원본의 "여러 항목 질문"(1,260개, 예: "아이노 원소랑 무기 알려줘")은 아직 지원하지 않는 유형이라 넣지 않았습니다. 지원할 때 같은 방식(학습용 캐릭터 = 개발용, 평가용 캐릭터 = 평가용)으로 나눕니다.
- 원본의 `info_v1` CSV는 고정 평가셋을 한글 칸으로 풀어 쓴 열람용입니다. 기준은 계속 `questions_info_v1.json`입니다.

## 정답 근거 문서 (evidence_info_v1.json)

답이 틀렸을 때 **검색이 근거를 못 찾았는지(검색 실패)**, **근거는 찾았는데 모델이 틀렸는지(답변 오류)** 나눠 보려고 문항마다 정답 근거 문서를 정해 두었습니다.

| 질문 종류 | 정답 근거 (`data/docs/documents_ko.jsonl`의 doc_id) |
|---|---|
| lookup | 질문한 캐릭터 문서 1개 (예: `character:albedo`) |
| filter | 정답 캐릭터 전부의 문서 |
| unknown | 없음 (검색 점수에서 제외) |

- 질문 문장은 보지 않고 정답과 캐릭터 이름으로만 정합니다. 라우터·검색을 고쳐도 정답 근거는 그대로입니다.
- 파일에는 611문항 전체의 정답 근거와 DEV 60문항 id(`dev_ids`, 노트북과 같은 60개)가 들어 있습니다.
- 다시 만들기: `python3 -m core.retrieval_eval --write` (테스트가 파일과 코드가 같은지 확인합니다)

### 검색 정확도 재기 (Hit@k)

`core/retrieval_eval.py`의 `evaluate_retrieval(내_검색_함수, 질문 목록)`에 검색 함수를 넘기면 유형별 지표가 나옵니다. 사용법은 파일 맨 위에 있습니다.

| 지표 | 뜻 | 주로 보는 곳 |
|---|---|---|
| hit@k | 정답 문서가 상위 k개 안에 하나라도 있으면 1 | lookup |
| recall@k | 정답 문서 중 상위 k개 안에 든 비율 | filter |
| all@k | 정답 문서가 상위 k개 안에 모두 있으면 1 | filter |

지금 키워드 검색(`core/router.py` + `core/retrieval.py`) 기준점: `python3 -m core.retrieval_eval`

| 질문 | hit@1 | filter recall@5 | filter all@30 |
|---|---|---|---|
| DEV 60문항 | 1.000 | 0.935 | 1.000 |
| 평가 115문항 | 1.000 | 0.903 | 1.000 |
| 말투 변형 개발용 1,748문항 | 0.681 (짧은 반말·존댓말 0.909, **띄어쓰기 없음 0.000**) | - | - |

- 템플릿 질문은 검색이 이미 만점입니다. 그래서 rag_v3의 오답(macro F1 0.563)은 **검색 실패가 아니라 답변 오류**입니다 → C의 프롬프트 개선 대상
- 벡터 검색은 이 기준점을 지키면서 **말투 변형 질문(특히 띄어쓰기 없음)** 을 얼마나 올리는지로 비교합니다 → B의 개선 대상
- 학습용(DEV) 질문은 평가용 캐릭터 문서를 검색하면 안 됩니다. `evaluate_retrieval`이 검사하고 어기면 멈춥니다.
