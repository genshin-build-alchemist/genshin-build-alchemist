# 보조 지표 기준 (정답률 · 거절 정확도 · 환각률)

노트북 `notebooks/03_aux_metrics.ipynb`가 계산하는 보조 지표 3개의 정의와 판정 기준이다.
주 지표는 집합 F1(macro F1)이고, 이 문서의 지표는 그 옆에서 "어떤 종류의 실수인지"를 보는 용도다.

## 1. 계산 대상

- **문항**: DEV 60문항 (`core/retrieval_eval.py`의 `dev_questions()`, 노트북 01 셀 10-1과 같다)
  - 캐릭터 조회(lookup) 40 (원소·무기·성급·지역 각 10), 조건 검색(filter) 16, 데이터 없음(unknown) 4
- **입력**: 이미 저장된 DEV 결과 JSON (`results/dev_*.json`). 모델을 다시 돌리지 않으므로 GPU가 필요 없다 (CPU 런타임)
- **출력**: `results/aux/aux_{실험 ID}.json`

## 2. 지표 정의

| 지표 | 계산 | 좋은 방향 |
|---|---|---|
| 정답률 | F1 = 1.0인 문항 수 ÷ 전체 문항 수 | 높을수록 |
| 거절 정확도 | unknown 문항 중 빈 답 `[]`을 낸 수 ÷ unknown 문항 수 | 높을수록 |
| 환각률 | 환각 문항 수 ÷ 답을 낸 문항 수 | 낮을수록 |

- **답을 냈다** = 답 목록을 정리한 뒤(아래 3-1) 하나라도 남은 것. 빈 답 `[]`은 환각률의 분모에서 빠진다
- 정답률은 이름이 하나만 틀려도 0으로 세는 엄격한 기준이다. 부분 점수는 macro F1로 본다

## 3. 환각 판정 기준

**환각 = 모델 답에 그 문항의 근거 문장에 없는 낱말이 하나라도 섞인 것.** 문항 단위로 센다 (한 문항에 여러 개가 섞여도 1건).

### 3-1. 판정 순서

1. **답 정리**: 답 앞뒤에 남은 `[ ] " '`를 지우고(`clean`), 빈 글은 버린다 (모델 답이 중간에 잘려 목록이 깨진 경우)
2. **근거 다시 찾기**: 결과 JSON에는 근거가 저장되어 있지 않아서, 같은 코드(`core/router.py` → `core/retrieval.py`)로 그 질문의 근거를 다시 찾는다
   - 학습용(DEV) 질문은 학습용 캐릭터 안에서만 찾는다 (평가용 캐릭터 22명 제외)
3. **허용 낱말 집합 만들기**: 근거 문장 `이름: 원소 X / 무기 Y / 5성 / 지역 Z`에서 이름, 원소, 무기, 성급, 지역을 뽑는다 (`core/answer.py`의 `evidence_words`). "정보 없음"은 뺀다
4. **표기 맞추기**: 양쪽 모두 같은 함수로 표기를 맞춘 뒤 비교한다 (`canonical`)
   - `불 원소` → `불`, `몬드 출신` → `몬드`, `5` · `5성급` · `★5` → `5성`, 따옴표 제거, 영문 소문자
   - 띄어쓰기·오타·다른 글자는 맞추지 않는다
5. **비교**: 허용 낱말 집합에 없는 답이 하나라도 있으면 환각 문항으로 세고, 그 낱말을 `not_in_evidence`에 남긴다

### 3-2. 예시

| 환각으로 센다 | 예 |
|---|---|
| 지어낸 이름 | `세탄`, `베티` |
| 오타 | `쿠피시노부` (근거에는 `쿠키 시노부`) |
| 다른 언어 글자가 섞인 이름 | `라이デン 쇼군` |
| 근거와 상관없는 값 | 바바라 출신 → `미국` |
| 답 형식이 깨진 것 | `yielded:`, `{'name': ...}` |

| 환각으로 세지 않는다 | 예 |
|---|---|
| 근거에는 있지만 정답이 아닌 이름 | "4성 번개 원소" 답의 `디오나`(얼음) → 환각이 아니라 **오답**. F1·정답률에서 깎인다 |

### 3-3. 후처리와의 관계

- 후처리(`_post`)는 답의 이름을 근거에 있는 이름 중 가장 비슷한 것으로 바꾸고, 없으면 버린다. 그래서 후처리 결과는 정의상 환각률이 0이 된다
- **환각률은 후처리 전 답(모델 원문)으로 계산한다.** `rag_v4+post`의 0은 "후처리가 환각을 모두 걸러냈다"는 뜻이다

## 4. 해석할 때 주의

- 환각률은 "근거에 없는 낱말"만 잡는다. 조건 검색의 주된 오답(근거 안에 있는데 조건에 안 맞는 이름)은 환각률에 나타나지 않는다
- unknown은 DEV에 4문항뿐이라 거절 정확도 1.0의 의미가 크지 않다
- 답을 거의 내지 않으면 거절 정확도는 높고 환각률 분모는 작아진다 (예: `prompt_v2`는 60문항 중 8개만 답함). 세 지표는 정답률·macro F1과 같이 본다
- 근거를 다시 찾으므로, 실험 당시와 지금의 `core/` 검색 코드가 같다고 가정한다. 검색 코드가 바뀐 뒤에는 그때의 결과 JSON과 맞지 않을 수 있다. 계산에 쓴 코드는 결과 JSON의 `config.code_version`에 남는다
